2. Hardware Architecture & Block Diagrams

2.1 Baseline AES-128 Iterative Datapath Architecture

The baseline core implements a 128-bit iterative architecture executing one AES encryption round per clock cycle (11 clock cycles total latency). Key expansion is computed on-the-fly via an internal round-key generator, eliminating large key-storage memories.

Figure 2.1: Synthesizable 128-bit Iterative AES-128 Baseline RTL Datapath Architecture.

2.2 First-Order Boolean Masking Architecture ($S' = P \oplus M$)

To decouple CMOS physical power consumption from secret data, sensitive intermediate variables are represented as two random shares: $$\text{Share 1 (Masked State): } S' = P \oplus M \quad\quad \text{Share 2 (Mask State): } M$$ Linear transformations ($ShiftRows$ and $MixColumns$) operate on both shares concurrently. SubBytes is executed across a protected boundary with dynamic mask refreshing. At the final output, $C = S'_{final} \oplus M_{final}$ recovers standard ciphertext.

Figure 2.2: First-Order Boolean Masked Architecture with Dual-Share Parallel Propagation.

3.3 Engineering Analysis: Why "Run Implementation" Requires Out-Of-Context (OOC) Mode

The 103 I/O Pin Placement Error & Its Professional VLSI Resolution:
When standard Vivado Implementation is run directly on the top-level cryptographic core, Vivado attempts to map all 517 parallel bus pins (128-bit Plaintext, 128-bit Key, 128-bit Mask, 128-bit Ciphertext, and controls) to external physical chip pins. However, the Artix-7 xc7a35tcsg324-1 package only has 210 physical user I/O pins, causing Vivado to report [Place 30-415] / [Place 30-68] (103 unplaced I/O errors).

In industry, cryptographic engines are designed as Internal Intellectual Property (IP) Cores embedded inside an SoC or connected via an AXI bus. They are synthesized and implemented in Out-Of-Context (OOC) Mode (-mode out_of_context), where logic placement and routing are performed completely inside the FPGA fabric without binding internal data buses to physical package pins. When implemented in OOC mode, the design finishes placement and routing with 0 Errors and 100% routability.

7. Roadmap for Final Review & Completion

  1. On-Chip Hardware PRNG Integration: Replace external testbench mask injection with an autonomous hardware pseudo-random number generator (e.g., 128-bit LFSR or Xorshift) to generate on-chip dynamic masks cycle-by-cycle.
  2. Composite-Field $\text{GF}((2^4)^2)$ S-Box: Replace the 256-entry lookup table with Canright composite-field arithmetic to suppress FPGA glitch-induced transient power leakage.
  3. Power-Trace Simulation & Statistical TVLA: Generate switching activity (VCD/SAIF) files from Vivado timing simulations and compute Welch's t-test (TVLA) statistics to confirm leakage suppression ($|t| < 4.5$).
